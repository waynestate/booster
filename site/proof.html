The three tool errors

On one large tree Rector ran out of its 1 GB memory limit. On another, Rector could not write its JSON report because a source file is not valid UTF-8. The third app was still running when the proof's 40 minute budget ran out, on a Docker host shared with other runs. In each case BOOSTER wrote nothing it could not account for. A memory option and a clean UTF-8 failure are queued; the overrun will be re-timed on a quiet host. The "older than 5.6" refusal above also names --from-php when the version came from composer.json; that message is queued for a fix too.

Liftoff · Your turn

Run it on your own app

Clone BOOSTER beside your app, read its plan, then let it run on a clean working tree. It never commits or pushes.

Install

git clone https://github.com/waynestate/booster.git && cd booster && composer install

See the plan

bin/booster plan --path=../my-app --today=2026-10-28

Run it, then read the diff

bin/booster run --path=../my-app --today=2026-10-28 && git -C ../my-app diff

The proof harness ran detect, plan and run --skip-gate inside php:8.4-cli on a throwaway git copy of each app, with .git, auth.json and every .env removed first, linted every changed PHP file in php:8.5-cli, and logged each app as one line (tool commit, unit id, command, exit code, duration, outcome) in the stack's internal record.

Splashdown · Small print

What this does not prove

  • Lint proves the code parses on PHP 8.5, not that it behaves the same. The test gate was skipped; a behaviour change is found by the app's tests and by review, which BOOSTER's notes on each hop say plainly.
  • No upgraded app was deployed or served. That is the next proof, on a test site.
  • composer update is never run by BOOSTER, so whether each app's dependencies resolve on 8.5 is not part of this run.
  • Nothing reached a database, a sign-in service or any Wayne State server.
  • Three tool errors stand until their fixes ship.
