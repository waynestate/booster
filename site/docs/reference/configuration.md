# Configuration[#](https://booster.apps.wayne.edu/docs/reference/configuration.html#configuration)

This page lists the environment variables Booster reads; the table is generated by the docs build.

| Variable | Meaning | Default | Read in |
| --- | --- | --- | --- |
| BOOSTER_BOT_TOKEN | Push token for the hop data robot (bin/hop-data-bot.php). Never in git, never logged, never printed | none | src/Refresh/HopDataBot.php |
| BOOSTER_POLICY | Path to CREED's policy.json | none (uses the policy.json in the waynestate/creed package) | bin/refresh-hop-data.php |

Booster reads the policy straight from the `waynestate/creed` package in its own `vendor/`, so there is no copy to drift: `composer update waynestate/creed` is the whole refresh. `--policy` and `BOOSTER_POLICY` still override it for one run.

`.env.example` holds the placeholder. Booster reads no secrets and talks to no Citadel host. Its own network calls only read: the dependency check asks Packagist (and any composer-type repository the app declares) about the app's direct dependencies, which `--no-package-check` turns off, and a plan for an app on `wayne-cas` with no `vendor/` checks the VCS repository `composer.json` names for that package with `git ls-remote`. Everything it prints from an app (file names, diffs) has control characters stripped.

When Rector runs, Booster passes it a few `BOOSTER_*` variables of its own (the app path, the sets, the PHP target). They are internal; do not set them.
