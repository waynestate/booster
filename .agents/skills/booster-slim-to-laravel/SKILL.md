# slim-to-laravel

Generated by `booster init`. Do not edit by hand.

Move a Slim 4 app onto Laravel 13 one unit at a time: sign-in on SESAME first, then Laravel at the root with the old app in legacy/, then routes and forms move run by run, each one gated by the replay.

This is the move onto Laravel (the strangler), not an upgrade: Laravel goes at the app root, the old app moves unchanged to legacy/, and units move over one run at a time. The replay is required, and it is the gate for every run. Read the guide (docs/guides/cakephp-and-slim-to-laravel.md) and this hop's notes before run 1.

1. `booster plan --path=<app> --to-laravel` and read every stop sign. The app must be on the framework's latest major, on PHP 8.3 or newer, committed, and have a filled-in replay file.
2. Run 1: `booster run --path=<app> --only slim-to-laravel --replay`. It does Step 0 (sign-in on SESAME), then the mount, then stops. Review, commit, deploy the mount with the Citadel public directory change.
3. Later runs: `booster run --path=<app> --only slim-to-laravel --replay --moves 1` moves the next unit in move order (stateless, page, write, signin). Commit after every green run. `--route "<id>"` moves one unit; `--hand --route "<id>"` flips a unit a person ported, once `route:list` shows it.
4. When no unit is left: `booster run --path=<app> --only slim-to-laravel --replay --finish` deletes legacy/, puts back the stock public/index.php and moves /login to Laravel.

When a gate fails, the run stops and leaves its changes in place; the units it moved are marked failed in booster-strangler.json:

1. Read the report: the replay answer that changed (the transcript names the request) or the syntax or legacy test output. Work from that exact output, the files it names, their tests and the notes below, not from a summary of them.
2. Fix one cause in the moved unit, then retry just that unit with `--route "<id>"`. A mount or finish that failed: undo it (`git checkout -- . && git clean -fd`) and run again once the cause is fixed.
3. A unit Booster refused (the report gives file:line) is ported by a person, then flipped with `--hand --route "<id>"`.
4. Stop after 3 tries at the same failure, or sooner when a try changes nothing. Show the person the last output and what you tried.

Never delete, skip or loosen a test to turn a gate green, and never add `--skip-gate`, `--allow-failing-baseline` or `--skip` unless the person asks for it.

Only if the app has Laravel Boost (`booster detect` says so):

- Use `list-routes` after each run and check that every unit the ledger marks laravel or hand is there, with the name the legacy route had.
- Use `search-docs` for the Laravel 13 docs on the feature a refused unit uses before you port it by hand.
- Use `get-config` to check the SESAME settings (SESAME_ROUTES, SESAME_CAS_SERVICE_URL) the Laravel half signs in with.
- Run `last-error` and `read-log-entries` after the replay.

Boost is read-only help. Booster's gate stays the authority: never skip a gate because Boost says so.

Check these by hand (the report groups its MANUAL lines the same way: sign-in, mount, route moves, finish):

- Opt in with --to-laravel. The planner puts the hop last, once the app is on Slim 4 and the plan reaches PHP 8.3 or newer.
- Run 1 does Step 0 (the legacy half signs in through SESAME) and the mount (Laravel at the root, the old Composer root moved unchanged to legacy/, the dispatcher in public/index.php), then stops. Each later run moves --moves N units (default 1), or one --route "<id>".
- The replay is required: no usable booster-replay.json, no strangler. The mount is checked against the untouched app with --serve-changed; later runs compare dispatcher against dispatcher.
- A unit Booster cannot move is refused with file and line. Port it by hand, then run --hand --route "<id>": Booster checks route:list, flips the route table and gates.
- The ledger, booster-strangler.json at the app root, is the state. Booster never commits: each run is one reviewable diff. A failed gate leaves the unit marked failed with the changes in place.
- When every unit has moved, --finish deletes legacy/ and the route table, puts back the stock public/index.php and moves /login to Laravel.
- Stop signs (nothing changes): not on the latest major, PHP under 8.3, a dirty tree, legacy/ or a Laravel app already at the root, no usable replay, an LTI app.
- MANUAL: the Citadel public directory becomes public (one dashboard change, deployed together with the mount), and dashboard config files move with their paths into legacy/.
