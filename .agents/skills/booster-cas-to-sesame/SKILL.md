# cas-to-sesame

Generated by `booster init`. Do not edit by hand.

Swap the wayne-cas package for SESAME native names: ModelUserResolver, auth.sesame, and the app's own ReadOnlyAttributes.

1. `booster run --path=<app> --dry-run` and read every diff.
2. `booster run --path=<app>` applies the plan and stops at the first failing gate.
3. If a hop is over the review threshold (200 files), read its per-rule summary, then apply it with `--max-changes=N`. Use `--skip` to leave a rule out.

When a gate fails, the run stops and leaves this hop's changes in place:

1. Read the report for this hop: the phase that failed and the last lines of output. Work from that exact output, the files it names, their tests and the notes below, not from a summary of them.
2. Fix one cause: code the hop could not change, a package that blocks the hop (`booster plan` names it), or a test that depends on old behavior.
3. Commit the fix on its own, then run `booster run --path=<app>` again. Booster plans from the versions the app is on now, so finished hops are not repeated.
4. Stop after 3 tries at the same failure, or sooner when a try changes nothing. Show the person the last output and what you tried.

Never delete, skip or loosen a test to turn a gate green, and never add `--skip-gate`, `--allow-failing-baseline` or `--skip` unless the person asks for it.

Only if the app has Laravel Boost (`booster detect` says so):

- Use `get-config` to copy the current wayne-cas settings before the swap.
- Use `list-routes` to note the sign-in and sign-out routes you will re-test.
- Run `last-error` and `read-log-entries` after a test login.

Boost is read-only help. Booster's gate stays the authority: never skip a gate because Boost says so.

What Rector cannot do (check these by hand):

- Booster writes config/sesame.php from config/wayne-cas.php when the old root is a plain string, or from SESAME's defaults when the app has no wayne-cas config at all, moves the CAS middleware from the web group onto the app's web routes under auth.sesame, removes any wayne.cas alias registration, points the web guard at the sesame driver and the users provider at eloquent (adding a model key when it has none), drops WayneCasable from user models, and moves a model's ReadOnlyAttributes trait to app/Models/Concerns. Booster removes config/wayne-cas.php when nothing in the app reads its config keys any more; otherwise it stays until those reads move to sesame.
- MANUAL: auth.sesame redirects an unauthenticated guest to the login route and answers a JSON request with 401, where wayne-cas answered 403.
- MANUAL: SESAME does not carry Duo two-factor. If the app had use2FA enabled, or DUO_* settings sit in an example env file, re-enable two-factor in the app itself and remove the dead DUO_HOSTNAME, DUO_IKEY, DUO_SKEY and DUO_AKEY settings; they do nothing under SESAME.
- SESAME is on Packagist: run composer require waynestate/sesame:^0.7.5 (no extra repository needed).
- SESAME (0.5 and later) binds each CAS sign-in to the browser that started it. The Laravel adapter passes the session itself, so no code change is needed; only an app that must accept a ticket for a login it did not start (a link from the CAS login page) sets SESAME_CAS_REQUIRE_PENDING_LOGIN=false, which reopens login CSRF.
- MANUAL: on Laravel 13 the session stores the user as JSON, so the app's SESAME resolver must implement RefreshesUser and look the user up again (SESAME docs, guides/laravel.md, "Reading the user").
- Log in through the pre-production host and check the session timeout and the Access ID attribute before you ship.
- Check that signed-in pages and any Gate or policy checks still work: auth()->user() now comes from SESAME's guard and is reloaded every request.
