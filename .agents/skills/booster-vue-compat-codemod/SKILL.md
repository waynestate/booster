# vue-compat-codemod

Generated by `booster init`. Do not edit by hand.

Run the vue-upgrade-tool codemod over the front end and keep every manual item it lists.

1. `booster run --path=<app> --dry-run` and read every diff.
2. `booster run --path=<app>` applies the plan and stops at the first failing gate.
3. If a hop is over the review threshold (200 files), read its per-rule summary, then apply it with `--max-changes=N`. Use `--skip` to leave a rule out.

Only if the app has Laravel Boost (`booster detect` says so):

- Use `search-docs` for the Vite front-end docs and check the app's build config against them.
- Use `browser-logs` after a page load to catch front-end errors the change might surface.
- Run `last-error` and `read-log-entries` after the build and the tests.

Boost is read-only help. Booster's gate stays the authority: never skip a gate because Boost says so.

What Rector cannot do (check these by hand):

- vue-upgrade-tool is lightly maintained; review every change it makes before you trust the diff.
- The tool lists the items it cannot fix; Booster keeps them in the hop result, so work through that list before you switch @vue/compat MODE to 3.
- The codemod needs @vue/compat in package.json, which the vue-27-to-compat hop installs; run that hop first.
