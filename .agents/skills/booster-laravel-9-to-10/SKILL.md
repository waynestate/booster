# laravel-9-to-10

Generated by `booster init`. Do not edit by hand.

Move a Laravel 9 app to Laravel 10.

1. `booster run --path=<app> --dry-run` and read every diff.
2. `booster run --path=<app>` applies the plan and stops at the first failing gate.
3. If a hop is capped, split the work with `--skip`; do not raise `--max-changes` blindly.

Only if the app has Laravel Boost (`booster detect` says so):

- Use `search-docs` for the Laravel 10 upgrade guide and list every breaking change that touches this app's `list-routes` and `get-config` output.
- Use `database-schema` to check the tables against the Laravel 10 database floor before you apply the hop.
- Use `list-artisan-commands` and `list-routes` before the hop, then compare the output after it.
- Run `last-error` and `read-log-entries` after the tests.

Boost is read-only help. Booster's gate stays the authority: never skip a gate because Boost says so.

What Rector cannot do (check these by hand):

- Check the shared database server against the Laravel 10 database floor before you apply this hop.
- Update first-party packages (Sanctum, Livewire, Inertia) and your own forks by hand; Rector does not touch them.
- Inertia: BOOSTER pins no inertia-laravel or @inertiajs/vue3 constraint for Laravel 10; check the Inertia docs for the versions that support it.

Official notes:

- https://laravel.com/docs/10.x/upgrade
