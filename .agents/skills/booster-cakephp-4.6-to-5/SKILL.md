# cakephp-4.6-to-5

Generated by `booster init`. Do not edit by hand.

Move a CakePHP 4.6 app to CakePHP 5.4 with CakePHP's own upgrade rules: AuthComponent moves to the Authentication plugin and .ctp templates become .php.

This is a framework move, not a PHP hop: the app's own tests rarely cover what it changes, so the replay is the real gate. Draft a replay file (`booster replay init`), read it, then `booster run --replay`. Read this hop's notes below before you apply it.

1. `booster run --path=<app> --dry-run` and read every diff.
2. `booster run --path=<app>` applies the plan and stops at the first failing gate.
3. If a hop is over the review threshold (200 files), read its per-rule summary, then apply it with `--max-changes=N`. Use `--skip` to leave a rule out.

When a gate fails, the run stops and leaves this hop's changes in place:

1. Read the report for this hop: the phase that failed and the last lines of output. Work from that exact output, the files it names, their tests and the notes below, not from a summary of them.
2. Fix one cause: code the hop could not change, a package that blocks the hop (`booster plan` names it), or a test that depends on old behavior.
3. Commit the fix on its own, then run `booster run --path=<app>` again. Booster plans from the versions the app is on now, so finished hops are not repeated.
4. Stop after 3 tries at the same failure, or sooner when a try changes nothing. Show the person the last output and what you tried.

Never delete, skip or loosen a test to turn a gate green, and never add `--skip-gate`, `--allow-failing-baseline` or `--skip` unless the person asks for it.

Only if the app has Laravel Boost (`booster detect` says so):

- Use `search-docs` for the CakePHP 5 migration guide and check it against every file Booster changed.
- Use `list-routes` (or the app's own route list) to pick the pages the replay file should hit.
- Use `list-routes` to pick one signed-in page per controller that used AuthComponent, and check that the Authentication plugin still sends a guest to sign in and lets a signed-in user through.
- Run `last-error` and `read-log-entries` after the replay.

Boost is read-only help. Booster's gate stays the authority: never skip a gate because Boost says so.

Check these by hand:

- AuthComponent moves to the Authentication plugin like for like: the same login form, the same session, the same user lookup.
- MANUAL: isAuthorized(), the authorize setting, loginRedirect, logoutRedirect and custom authenticators stay as they are; move them to the Authorization and Authentication plugins by hand.
- Templates (.ctp) are renamed to .php under templates/.
- App bugs the move exposes are reported, never fixed: the hop moves the framework, not the app's own logic.
